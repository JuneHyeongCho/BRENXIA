# BRENXIA 인프라 아키텍처 및 핵심 설정값 (영구 보존용)

본 문서는 대화 기록(Context)이 압축되거나 손실되더라도 절대 잊어버리지 않도록, 프로젝트의 핵심 인프라 설정값과 구조를 영구적으로 박아두는 기준(Anchor) 문서입니다.

## 1. 서버 아키텍처 이원화 구조
본 프로젝트는 **비용 최적화 및 보안**을 위해 데이터를 굽는 로컬 장비와 외부 통신을 담당하는 클라우드 VPS 장비를 철저하게 분리하여 운영합니다.

### A. 로컬 데이터 구축 서버 (현재 작업 중인 컴퓨터)
- **역할**: 대용량 PDF 문서들의 파싱, 임베딩 처리 및 벡터 데이터베이스(RAG) 생성 (비용이 발생하는 무거운 연산을 무료로 오프라인 처리)
- **핵심 컴포넌트**: `rag_ingest.py`, `HuggingFace 로컬 모델 (paraphrase-multilingual-MiniLM-L12-v2)`, `ChromaDB`
- **저장 위치**: `data/chroma_db/`

### B. 프로덕션 메인 서버 (호스팅어 VPS)
- **역할**: 완성된 RAG 데이터베이스를 바탕으로 실제 구글 챗봇(Webhook)과 통신하며 BRENXIA 에이전트를 구동하는 24시간 라이브 서버.
- **공인 IP**: `72.62.65.177`
- **도메인**: `agent.brenxia.com` (가비아 DNS 연동 완료)

## 2. 프로덕션 서버(VPS) 세부 설정 (페이퍼클립)
- **운영 환경**: Docker 기반 (도커 매니저 사용)
- **메인 컨테이너**: `paperclip`
- **라우팅/HTTPS**: `Traefik` (도메인 연결 및 SSL 자동화)
- **환경 변수(Env) 핵심값**:
  - `VPS_IP` = `72.62.65.177`
  - `TRAEFIK_HOST` = `agent.brenxia.com`
  - `ADMIN_EMAIL` = `brenxia@brenxia.com`

## 3. 배포 파이프라인 (작업 흐름)
1. **[로컬]** 로컬 PC에서 71권 이상의 방대한 PDF를 무제한/무료로 분쇄하여 `data/chroma_db`를 굽습니다.
2. **[전송]** 굽기가 완료된 `chroma_db` 폴더(뇌)를 호스팅어 VPS(72.62.65.177) 서버로 복사/업로드하여 이식합니다.
3. **[구동]** VPS 내부의 페이퍼클립(paperclip) 도커 컨테이너를 가동하여, 구글 챗봇이 `agent.brenxia.com`을 통해 지식에 접근하도록 연결합니다.

> **⚠️ AI 에이전트 주의사항**
> 작업 중 맥락이 상실되거나 네트워크/DNS 설정에 대한 의문이 생길 경우, 임의로 상상(Hallucination)하지 말고 **반드시 이 문서를 최우선으로 참고**하여 호스팅어 VPS와 페이퍼클립 아키텍처를 복구할 것.
