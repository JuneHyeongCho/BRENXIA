# BRENXIA 양방향 지식 순환 아키텍처 (Bi-directional Knowledge Loop)

이 문서는 향후 BRENXIA 에이전트와 사용자의 로컬 옵시디언(Obsidian) 간에 지식이 끊임없이 상호작용하며 진화하는 **[옵시디언 ↔ 깃허브 ↔ 에이전트 양방향 순환 파이프라인]** 구축 아젠다입니다.

## 1. 아키텍처 개요: 자가 진화형 지식 루프 (Self-Evolving Knowledge Loop)
단방향 데이터 주입이나 단순 아카이빙을 넘어, 에이전트와 옵시디언 간의 '끊임없는 상호작용(Interaction)'을 구현합니다.

* **[Phase 1. 기초 학습]**: 사용자가 옵시디언에서 초기 지식(룰, 가이드라인)을 작성하여 깃허브를 통해 에이전트에게 주입(학습)합니다.
* **[Phase 2. 창조 및 위키 링크(Wiki-link) 아카이빙]**: 에이전트가 업무를 수행하고 새로운 통찰을 생성하면, 단순한 텍스트가 아닌 **옵시디언 위키(Obsidian Wiki) 포맷**으로 산출물을 만듭니다. (예: `[[프로젝트명]]` 같은 쌍방향 링크와 `#태그`, YAML 메타데이터 포함). 이를 통해 새 문서가 기존 지식 네트워크(Knowledge Graph)에 거미줄처럼 자동 연결됩니다.
* **[Phase 3. 재학습 (Re-learning)]**: 옵시디언 위키에 유기적으로 연결된 산출물을 사용자가 확인/보완하면, 에이전트는 이 거대한 거미줄(지식망) 자체의 맥락을 **다시 자신의 RAG 벡터 DB로 빨아들여 재학습**합니다.

## 2. 해결되는 문제점 (Solved Problems)
* **휘발성 데이터의 영구 자산화**: 에이전트가 구글 챗에서 쏟아내는 수많은 통찰과 결과물이 허공으로 사라지지 않고, 옵시디언 제2의 뇌에 차곡차곡 쌓여 영구적인 지식 자산이 됩니다.
* **에이전트 지능의 복리 성장**: 한 번 만들어진 데이터가 다시 에이전트의 학습 데이터로 재투입되므로, 에이전트의 상황 인지 능력과 문제 해결 능력이 사용할수록 기하급수적으로 똑똑해집니다.
* **완벽한 통제권 유지**: 에이전트가 무슨 데이터를 새로 만들었는지 옵시디언을 통해 사람이 직접 눈으로 확인하고 구조를 통제할 수 있습니다.

## 3. 향후 구현 단계 (Next Implementation Steps)
1. **[Git 양방향 동기화 세팅]**: 로컬 옵시디언(Obsidian Git)과 VPS 에이전트 간의 자동 Push/Pull 양방향 통신 브릿지 구축.
2. **[에이전트 아카이버(Archiver) 개발]**: 헤르메스가 의미 있는 대화나 결과물을 도출했을 때, 이를 `.md` 파일로 변환하여 깃허브에 Push하는 파이썬 모듈 개발.
3. **[자동 재학습(Re-ingest) 트리거]**: 옵시디언에서 넘어온 신규/수정된 파일을 에이전트가 감지하여 즉시 ChromaDB를 업데이트하는 로직 연동.
