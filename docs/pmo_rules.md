# BRENXIA PMO 직능 규칙 문서 (PMO Rules)

이 문서는 브랜드 익스피리언스 솔루션 그룹 **브렌시아(BRENXIA)**의 프로젝트 관리 자동화 및 오케스트레이션을 담당하는 **PMO 직능(PMO Job Function)**의 세부 기능 작동 규칙을 정의한 문서입니다.

---

## 1. PMO 파트 역할 및 사양 (CEO & Orchestrator R&R)

### ① 헤르메스 에이전트 (Hermes Agent / CEO)
* **소통 및 지휘 허브**: 구글 챗(Google Chat)을 기반으로 활동하며, 페이퍼클립 조직도상 최고 책임자(CEO)로서 에이전트들의 상태와 WBS 일정을 총괄 관리합니다.
* **입력(Input)**: 휴먼의 필수 정보 입력, 산출물 업로드 이벤트, 결재 승인 및 동의 시그널.
* **산출물(Output)**: 구글 챗 스페이스(Space), 드라이브 폴더 구조, WBS 및 수치 알림.
* **핵심 역할 및 오케스트레이션(Orchestration)**:
  1. **인프라 자동 구축**: 프로젝트 킥오프 시 드라이브 6대 표준 폴더를 열고 일정을 스프레드시트에 WBS로 등록 및 관리합니다.
  2. **하부 조직 가동 및 조율**: 페이퍼클립에 소속된 서브 에이전트들의 진행 상태(Status)를 트래킹하고, 의견 대립 발생 시 조율안을 제안합니다.
  3. **버전 및 잠금 매니징**: 신규 파일 업로드 시 구버전을 아카이브 폴더로 이동시키는 버저닝 및 완료 시 드라이브 접근 권한을 읽기 전용으로 제어합니다.
  4. **지식 자산화 연동**: 완료된 프로젝트 자료를 데이터베이스(DB)화하여 차기 유사 프로젝트 착수 시 관련 완료 데이터를 자동 추천·열람시킵니다.

## 2. 프로젝트 생성 및 착수 단계 규칙 (Initiation & Kick-off)

### ① 개설 요청 및 하이브리드 개설선
1. **프로젝트 개설 신청**:
   - 휴먼 담당 PM (Human Lead PM)이 헤르메스 에이전트에게 3대 필수 정보(광고주명, 브랜드명, 프로젝트명)와 함께 **CEO 승인 필요 여부 (Y/N)**를 선택하여 개설을 요청합니다.
   - 개설 신청 시 헤르메스는 구글 챗 입력 폼에 **[CEO 승인 판단 가이드라인]**을 제공합니다.
     - *가이드라인 기준*: 경쟁 비딩(PT) 건, 전사 기준액(예: 1억 원) 이상의 예산 규모, 또는 회사 브랜딩에 직접적인 영향을 주는 핵심 전략 프로젝트인 경우 **'Y (승인 필요)'**를 선택합니다.
2. **개설 승인 및 배포 분기**:
   - **즉시 개설 (CEO 승인 제외 - 'N' 선택 시)**: 별도의 승인 대기 없이 구글 챗 스페이스 및 구글 드라이브 전용 폴더가 즉시 자동 배포됩니다.
   - **CEO 승인 개설 (CEO 승인 필요 - 'Y' 선택 시)**: 헤르메스 에이전트가 최종의사결정자(CEO)에게 3대 정보(광고주명, 브랜드명, 프로젝트명)가 수록된 승인 카드를 발송하고, 승인 시 인프라가 배포됩니다.
3. **지연 시 대체 작동 규칙 (Fallback Rule for Delay)**:
   - CEO 승인 필요(Y)로 요청된 후 **12시간 동안 승인이 지연되는 경우**, 실무 병목을 방지하기 위해 헤르메스가 자동으로 인프라를 **'임시 개설(Read/Write 가능하나 [미승인] 태그 부착)'** 상태로 배포하여 실무 착수를 허용하며, 사후 승인을 받도록 알림을 발송합니다.
4. **결재선 상태의 동적 전환 (Dynamic Route Transition)**:
   - 최초에 CEO 승인 제외(N)로 즉시 개설되었더라도, 진행 도중 규모 확대나 중요도 상승 시 PM이 구글 챗 명령(`@헤르메스 결재선 변경`)을 통해 **CEO 승인 대상 프로젝트로 즉시 전환**하여 사후 결재선을 추가할 수 있습니다.
5. **리소스 클린업 및 사후 감사(Audit)**:
   - *리소스 클린업 규칙*: 무분별한 리소스 낭비를 방지하기 위해 개설 후 48시간 내에 폴더 내 산출물이 1개도 등록되지 않으면 헤르메스 에이전트가 챗으로 알림 후 프로젝트를 자동 보관(Clean-up/Archived) 처리합니다.
   - *사후 감사(Audit) 규칙*: 보안 공백 방지를 위해 프로젝트 개설 즉시 프로젝트 관리자(Admin) 계정에 읽기/쓰기 권한을 자동으로 부여하며, 매주 월요일 생성된 전체 프로젝트 요약 리포트를 Admin에게 자동 발송하여 사후 모니터링을 보장합니다.
6. **책임자 정보 사후 검증 규칙 (Responsible Director Verification)**:
   - 사전 보류 배제 규칙: 프로젝트를 개설하기 전 기획/제작 책임자의 지정 여부를 검증하여 개설을 보류(Hold)하지 않습니다.
   - 사후 점검 및 리마인드: 프로젝트 개설 완료 후, 헤르메스 에이전트는 **WPMS 사전예측 시트**를 주기적으로 모니터링하여 **기획/운영 책임자 (PD)** 및 **제작 책임자 (CD)**의 계정 정보가 정상적으로 기입되어 있는지 점검합니다. 정보 누락이 감지될 경우, 에이전트는 인프라 개설을 보류하지 않는 대신 담당 휴먼 PM에게 구글 챗으로 정보 입력을 요청하는 리마인드 알림 카드를 전송합니다.

## 3. 프로젝트 라이프사이클 및 드라이브 연동 지침 (Lifecycle & Foldering)

### ① PMS 디렉터리 경로 및 파일 명명 규칙 (PMS Directory & Naming Rules)
1. **PMS 공유 드라이브 루트**: `공유 드라이브/BRENXIA_PMS/`
2. **연도별 PMS 폴더**: `.../BRENXIA_PMS/[YYYY]_PMS/` (예: `2026_PMS`)
3. **광고주별 PMS 파일 명명 규칙**: 광고주 단위로 프로젝트 관리 시트(PMS) 파일이 분리되어 저장됩니다.
   - *파일명 규격*: **`BRENXIA WPMS_[광고주명].gsheet`** (구글 스프레드시트 포맷)
   - *실무 적용 예시*: `공유 드라이브/BRENXIA_PMS/2026_PMS/BRENXIA WPMS_마스터카드.gsheet`
4. **광고주당 단일 PMS 파일 유지 원칙 (One PMS File Per Client)**:
   - 에이전트는 광고주 단위로 단 하나의 PMS 파일만 생성 및 관리합니다. 특정 광고주 하위에 신규 프로젝트가 추가되거나 기존 프로젝트에서 파생 프로젝트가 발생하더라도 **프로젝트별로 별도의 WPMS 파일을 생성해서는 안 되며**, 오직 기존에 존재하는 해당 광고주의 `BRENXIA WPMS_[광고주명].gsheet` 파일 내 월별 탭(1월~12월)에 **새로운 행(Row)으로만 추가하여 관리**해야 합니다.
5. **동적 파일 매칭**: 폴더 생성 시 오타나 띄어쓰기 차이로 인한 매칭 실패를 막기 위해, 에이전트는 광고주명을 비교할 때 공백을 제거한 소프트 매칭(Soft Matching)을 적용하여 기존 파일을 탐색합니다.

### ② 드라이브 인프라 자동 개설 (Folder Hierarchy)
프로젝트 개설 즉시 공유 드라이브의 연도별 폴더(`BRENXIA_PROJECT/[YYYY]년/`) 아래에 **`[YYMMDD]_[광고주_브랜드_프로젝트명]`** 형식으로 프로젝트 루트 폴더를 자동 생성하고 7대 표준 하위 폴더를 자동 생성합니다.
* `00.고객사 제공자료` (RFP, 기초 데이터 보관)
* `01.제안` (제안서 보관)
* `02.기획` (전략 브리프 등 기획 문서 보관)
* `03.제작` (카피라이팅 시안, 비주얼 이미지 시안 보관)
* `04.미디어` (미디어 효율 의견서 등 보관)
* `05.행정` (계약서 및 정산 서류 보관)
* `06.PMS` (광고주별 PMS 관리 시트 보관)

### ③ 외부 협업사 권한 제어 규칙 (External Partner Access Control)
1. **브렌시아 도메인 제한**: 브렌시아 공식 도메인 계정(`@brenxia.com`)이 아닌 외부 파트너(디자이너, 프로덕션, 개발사 등)에게는 프로젝트 드라이브 접근 및 사용을 원칙적으로 엄금합니다.
2. **제한적 임시 권한 부여**: 실행(Execution) 단계에서 부득이하게 외부 협업 인력이 구글 챗에 초대될 경우, 에이전트는 [외부 협업사 권한] 옵션을 활성화하여 `05.행정` 및 `04.미디어` (원가 자료 보관) 폴더를 제외한 **`01.제안` ~ `03.제작` 폴더에만 임시 읽기/쓰기 권한**을 부여하도록 제한합니다.

### ④ 라이프사이클별 PMS-드라이브 상세 연동 프로세스 (Lifecycle & Folder Archiving Process)

```mermaid
graph TD
    %% 제안 개설 요청
    Start([제안 프로젝트 개설 요청]) --> FindPMS{BRENXIA_PMS/[YYYY]_PMS 하위에<br>BRENXIA WPMS_[광고주명] 존재?}
    FindPMS -->|No 없음| CreatePMS[마스터 템플릿 복사하여<br>BRENXIA WPMS_[광고주명] 파일 신규 생성]
    CreatePMS --> AddRow[해당 시트에 신규 행 추가<br>상태: 제안]
    FindPMS -->|Yes 있음| AddRow
    
    %% 상태 변경 감지
    AddRow --> StatusChange{프로젝트 상태 변경?}
    StatusChange -->|수주 Won| UpdateWon[PMS 시트 상태 '운영' 변경<br>드라이브 폴더명 '운영'으로 갱신]
    StatusChange -->|실주 Lost| UpdateLost[Lost Reason 챗 수집<br>자산 마스킹 및 별도 복사<br>드라이브 폴더명 '실주' 갱신 후 99_아카이브 이동]
    StatusChange -->|홀딩 Paused| UpdateHolding[인력 상태 '가용 가능' 자동 변경<br>구글 챗 리포팅]
    StatusChange -->|완료 Closure| UpdateFinished[PMS 시트 상태 '완료' 변경<br>99_아카이브 이동 및 하이브리드 잠금]
```

1. **신규 프로젝트 제안 (Proposal)**:
   - 에이전트가 `[YYYY]_PMS` 폴더 아래에서 해당 광고주의 `BRENXIA WPMS_[광고주명].gsheet` 파일을 검색합니다.
   - 시트가 존재하지 않을 경우, 기본 마스터 템플릿을 복사하여 신규 생성합니다. 이 단계에서 지정된 **기획/운영 책임자(PD)** 및 **제작 책임자(CD)**에게만 쓰기(편집) 권한을 부여합니다.
   - 해당 월 탭에 새 행(Row)을 추가하여 기본 정보를 입력하고 상태를 **`제안`**으로 설정합니다.
   - 구글 드라이브에는 `BRENXIA_PROJECT/[YYYY]년/[YYMMDD]_제안_[프로젝트명]` 폴더를 생성합니다.
2. **수주 및 운영 전환 (Won & Execution)**:
   - 수주 확정 시, 에이전트는 개별 PMS 시트 내의 프로젝트 행 상태를 **`운영`**으로 변경합니다.
   - 동시에 구글 드라이브의 폴더명을 `[YYMMDD]_제안_[프로젝트명]`에서 **`[YYMMDD]_운영_[프로젝트명]`**으로 자동 변경합니다.
3. **실주 처리 및 자산 마스킹 (Lost & Masking)**:
   - 제안 결과가 실주(Lost)로 확정되면, 에이전트는 구글 챗 카드를 발송하여 휴먼 PM에게 실주 원인을 제출하도록 유도하고 이를 연간 실주 통계에 축적합니다.
   - 개별 PMS 시트 내의 프로젝트 행 상태는 **`실주`**로 변경합니다.
   - 광고주의 기밀 정보(RFP 내용 등)가 포함된 문서는 보안 잠금 폴더로 이동시키고, 아이디어성 제작 시안들은 기밀 내용을 마스킹한 뒤 **`BRENXIA 크리에이티브 아카이브`** 폴더로 별도 복사하여 자산화합니다.
   - 구글 드라이브 폴더명은 **`[YYMMDD]_실주_[프로젝트명]`**으로 변경한 뒤, **`99_아카이브`** 폴더 하위로 기계적으로 이동시켜 보관합니다.
   - *실주/드랍 시 실제 투입일 입력 강제*: 프로젝트가 실주 또는 드랍되더라도, 중단 시점 이전까지 실제로 인력이 투입된 일수 및 M/M 데이터는 반드시 정량 수치로 시트에 반영되어 기록 보존되어야 합니다.
4. **프로젝트 일시 정지 (Hold & Resource Release)**:
   - 프로젝트가 일시 정지(Hold)되면 투입인력의 유휴 상태를 방지하기 위해, 에이전트는 홀딩 시점 이전까지의 실제 투입일 및 M/M 데이터가 정량 수치로 시트에 기입 및 보존되도록 리마인드합니다.
   - 동시에 HR 시스템 상에서 해당 인력들의 상태를 **`가용 가능(Available)`**으로 자동으로 업데이트하도록 협업 조율합니다.
5. **프로젝트 완료 및 아카이빙 (Completion)**:
   - 프로젝트 정상 종료 시, PMS 상태를 **`완료`**로 변경하고, 드라이브 폴더 구조를 **`99_아카이브`** 폴더로 이동합니다.
   - `05.행정` 폴더를 제외한 모든 실무 폴더를 즉시 **읽기 전용(Read-only)**으로 잠급니다.

## 4. PMS 구글 스프레드시트 연동 및 수치 검증 규칙 (PMS Integration)

### ① WPMS 파일 작성 권한 제한 규칙 (WPMS Write Access Restriction)
1. **책임자 한정 쓰기 권한**: `BRENXIA WPMS_[광고주명].gsheet` 파일의 작성(쓰기 및 수정) 권한은 프로젝트 참여인원 중 오직 **기획/운영 책임자 (PD)** 및 **제작 책임자 (CD)**로 지정된 담당 휴먼 계정에만 한정하여 부여합니다.
2. **일반 실무자 및 파트너 작성 제한**: 기획/제작 책임자를 제외한 일반 실무자(AP, AE, CW, AD, Designer 등) 및 외부 파트너사에게는 정량적 재무 데이터 훼손 방지를 위해 해당 WPMS 시트에 대한 작성 권한을 절대 부여하지 않으며, 오직 조회(Read-only) 권한만 부여하거나 접근을 차단합니다.

### ② 필수 수치 데이터 입력 점검 및 리마인드 알림 (Data Validation & Reminder)
* 에이전트는 프로젝트의 상태가 변경될 때 또는 매월 정산 시점(매월 25일)에 각 시트의 수치 입력 상태를 점검합니다.
* **빈 칸 검증 원칙 (Null-only Validation)**: 
  - 수치가 실제로 발생하지 않아 수치가 **`0`**일 가능성을 고려하여, **수치가 완전히 비어 있는 빈 칸(Null/Empty)인 경우에만 누락으로 취급**하며, 사용자가 명시적으로 숫자 **`0`**을 기입한 경우에는 정상적으로 입력이 완료된 값으로 판단하여 리마인드 알림 대상에서 제외합니다.
  - `청구금액`, `매입금액` 및 TF투입인력 M/M 산출표의 `투입일`, `M/M` 등 필수 항목이 완전히 비어 있는 빈 칸(Null)으로 누락된 경우, 에이전트가 즉시 감지하여 구글 챗 프로젝트 스페이스 또는 담당 휴먼 PM의 1:1 다이렉트 메시지(DM)로 **\"[수치 누락 알림] 필수 수치(매출/매입 금액 혹은 M/M 투입일)가 누락되었습니다. 입력을 완료해 주세요.\"**라는 카드를 발송하고 해당 시트의 바로가기 링크를 제공합니다.

## 5. 자동 버전 관리 및 아카이빙 지침 (Auto Version Control)

각 프로젝트의 6대 표준 폴더(`00.고객사 제공자료` ~ `05.행정`) 내부의 파일 어지러짐(Clutter)을 방지하고 항상 최신본을 직관적으로 확인할 수 있도록, 에이전트는 다음과 같은 자동 버전 관리 규칙을 강제합니다.

### ① 아카이브 폴더 정리
1. **아카이브 하위 폴더 생성**: 각 표준 폴더(예: `02.기획`, `03.제작`) 내부에는 자동으로 **`_이전버전_아카이브`** 폴더가 생성됩니다.
2. **최신 파일 단일화 (Single Source of Truth)**: 각 표준 폴더의 최상위 루트에는 항상 **단 하나의 가장 최신 버전(최종본)** 파일만 위치시킵니다.

### ② 버전 감지 및 파일 자동 이동 (Version Push-down)
1. **신규 버전 업로드 감지**: 사용자가 챗이나 드라이브에 신규 버전 파일(예: `260116_우리카드_기획서_V1.1.pptx`)을 업로드하면 에이전트가 파일명을 기반으로 버전을 감지합니다.
2. **이전 버전 백업**: 새로운 파일이 루트에 위치하는 즉시, 기존에 있던 구버전 파일 (`260116_우리카드_기획서_V1.0.pptx`)을 자동으로 `_이전버전_아카이브` 폴더로 이동시킵니다.
3. **정리 결과 보고**: 에이전트는 구글 챗에 "이전 버전(V1.0)을 아카이브로 백업하고 최신 버전(V1.1)을 폴더 루트에 업데이트했습니다"라고 보고합니다.
4. **WBS 상태값 갱신(스프레드시트 동기화) 트리거 제어**:
   - 실시간 문서 편집 시 발생하는 잦은 상태 채터링(Chattering)과 알림 소음을 막기 위해, 업로드된 파일명에 `*_최종_*` 또는 `*_V1.0_*` 등 명확한 버전 패턴이 매칭될 때에만 에이전트가 구글 챗에 **\"WBS 상태를 '검토 대기'로 업데이트할까요?\"**라는 컨펌 카드를 전송하고, 사용자가 승인할 때에만 스프레드시트 상태 변경 및 다음 에이전트 라우팅이 가동되도록 제한합니다.

## 6. 하이브리드 파일 잠금 규칙 (Hybrid Lock Rules)

* 프로젝트 완료(Closure) 시 모든 드라이브 폴더의 접근 권한을 읽기 전용(Read-only)으로 즉시 잠급니다.
* 단, 세금계산서 발행 및 최종 정산이 빈번한 `05.행정` 폴더에 대해서는 휴먼 PM이 구글 챗에서 **[정산 잠금 승인]**을 누를 때까지 쓰기 권한 잠금을 임시 보류(Deferred Lock)하고 유예합니다.
* 완료 시, `00.고객사 제공자료`부터 `04.미디어` 폴더까지는 **즉시 읽기 전용으로 잠금** 처리합니다.
